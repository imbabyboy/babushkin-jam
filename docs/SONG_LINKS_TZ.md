# ТЗ: сервис ссылок на песню

Статус на 3 ноября 2026: сервис развёрнут на тестовом адресе `/links/` сервера комнат, кнопка в приложении есть. Домена и ключей пока нет. `service.com` ниже — временное название.

## 1. Зачем

Не у всех есть Яндекс Музыка, поэтому ссылка на трек работает не для всех. Сервис по названию песни находит её на других площадках и отдаёт одну страницу со всеми ссылками. Этой страницей можно поделиться, например в Telegram.

Сервис только ищет и показывает ссылки. Музыку он не скачивает, не хранит и не передаёт.

## 2. Что должно получиться

1. **Сайт.** На главной поле «Вставьте название песни». После ввода показывается список сервисов со ссылками.
2. **Прямая ссылка с параметрами.** `service.com?singer=kizaru&songname=trooper` сразу показывает результат.
3. **Кнопка в приложении.** В плейлисте рядом с «Скопировать» появляется кнопка «Уйти на сайт». Она открывает в браузере страницу сервиса с параметрами трека.

Если песни на сервисе нет, в его строке стоит прочерк. Если сервис проверить не удалось, вместо прочерка ссылка «Искать».

| --- | --- | --- |
| Яндекс Музыка | первый | официального API нет, см. раздел 6 |
| YouTube | первый | |

Новый сервис добавляется одним файлом в `providers/`, остальной код не меняется.

## 3. Параметры ссылки

| Параметр | Что значит | Пример |
| --- | --- | --- |
| `q` | свободный текст, так ищет форма на сайте | `kizaru trooper` |
| `singer` | исполнитель | `kizaru` |
| `songname` | название песни | `trooper` |
| `album` | название альбома | `Karmageddon` |
| `year` | год, уточняет выбор | `2021` |
| `duration` | длительность в секундах, уточняет выбор | `184` |
| `ym` | номер трека в Яндекс Музыке: `альбом/трек` или `трек` | `6017146/44856424` |

Что ищем:

| Переданы | Результат |
| --- | --- |
| `singer` + `songname` | ссылки на песню |
| `singer` + `songname` + `album` | ссылки на песню именно из этого альбома; если на сервисе такого альбома нет, то на эту же песню из другого альбома |
| `singer` + `album` или только `album` | ссылки на альбом |
| только `singer` | ссылки на страницу исполнителя |
| только `songname` или `q` | лучшее совпадение и его ссылки |
| ничего | пустая главная с формой |

Правила:

- Неизвестные параметры игнорируются, чтобы старые ссылки не ломались.
- Длина каждого значения ограничена 200 символами, лишнее обрезается.
- При переданном `ym` ссылка на Яндекс строится сразу, без поиска. Так приложение всегда получает точную ссылку, даже если поиск Яндекса на сервере не заработает.

## 4. Поиск без цензуры

- Сервис не фильтрует запросы и результаты по словам.
- Где API это позволяет, фильтры площадки выключены: `safeSearch=none` у YouTube, `explicit=Yes` у Apple.
- Если есть обычная и «чистая» (clean) версии песни, выбирается обычная. «Чистая» показывается только если других нет или если её запросили.
- На сайте у таких треков стоит пометка `E`, если площадка её отдаёт.

Ограничение: треки, которые площадка убрала из выдачи или закрыла по стране, сервис найти не сможет.

## 5. Как сервис выбирает правильный трек

Неверная ссылка хуже прочерка, поэтому при сомнении показываем прочерк.

1. **Нормализация:** нижний регистр, `ё` → `е`, убрать `feat.`/`ft.`, пунктуацию и лишние пробелы.
2. **Сравнение названий:** латиница и кириллица сравниваются и как есть, и через транслитерацию (`kizaru` / `кизару`).
3. **Оценка кандидата:**
   - исполнитель должен совпасть, без этого кандидат отбрасывается;
   - название должно совпасть;
   - `duration`, если передан, должен отличаться не больше чем на 5 секунд;
   - версии `remix`, `live`, `instrumental`, `karaoke`, `cover`, `sped up`, `slowed` отбрасываются, если их не просили.
4. **YouTube:** в первую очередь официальные каналы и каналы `- Topic`.
5. **Без порога и нечёткого сравнения:** кандидат либо проходит правила, либо отбрасывается. Похожие названия дают чужие песни.

## 6. Источники данных

Что известно на 3 ноября 2026. Яндекс, Apple, Deezer и страницы поиска проверены с VPS. API Spotify, YouTube и SoundCloud с ключами не проверены: код написан по документации.

| Сервис | Способ | Условия и риски |
| --- | --- | --- |
| Яндекс Музыка | только ссылка из `ym` | Публичного API нет. Неофициальный поиск без токена с VPS отвечает `451` (проверено 3 ноября 2026, сервер в Нидерландах). Токен пользователей на сервер не попадает никогда. При вводе на сайте — прочерк |
| YouTube | Data API v3 | `search.list` стоит 100 единиц, по умолчанию это около 100 поисков в день на проект. Нужны кэш и защита квоты |
| Spotify | Web API | Для Development Mode владельцу приложения нужен Premium. По сторонним источникам, в поиске максимум 10 результатов, а токен client credentials может вести себя иначе. Официально не подтверждено |
| SoundCloud | официальный API, client credentials | Поиск без входа пользователя поддерживается, но для регистрации приложения нужен аккаунт Artist Pro. Токен живёт около часа, его выпуск ограничен, поэтому токен кэшируем |
| YouTube Music | страница поиска | Публичного API нет. Находит сами треки, а также альбомы и исполнителей |
| Apple Music | iTunes Search API | Без ключа, примерно 20 запросов в минуту. Часть песен отдаёт только с цензурой, часть не находит: на сайте это видно пометкой и прочерком |
| Deezer | публичный API | Работает без ключа, в том числе с VPS. Лимит около 50 запросов за 5 секунд по сторонним источникам |

Без ключей YouTube, YouTube Music и SoundCloud читаются со страницы поиска: выбирается первый результат, прошедший проверку из раздела 5. Условия этих сервисов автоматический доступ запрещают, возможна блокировка IP сервера, поэтому есть `PAGE_SEARCH=off` и предел запросов в день. Страница показывает только начало выдачи, поэтому если совпадения нет, вместо прочерка остаётся «Искать». Spotify отдаёт результаты только после выполнения JS в браузере, у него остаётся «Искать».

Страна поиска задаётся настройкой. Найденный трек может быть недоступен по ссылке в другой стране: сервис этого не проверяет.

## 7. API сервиса

`GET /api/search` принимает параметры из раздела 3.

```json
{
  "query": { "singer": "kizaru", "songname": "trooper" },
  "kind": "track",
  "title": "Trooper",
  "artist": "kizaru",
  "cover": "https://...",
  "results": [
    { "service": "yandex", "status": "found", "url": "https://music.yandex.ru/album/1/track/2", "explicit": true },
    { "service": "spotify", "status": "not_found" },
    { "service": "youtube", "status": "unavailable", "reason": "quota", "searchUrl": "https://www.youtube.com/results?search_query=..." }
  ],
  "cached": false
}
```

| `status` | Значение | На сайте |
| --- | --- | --- |
| `found` | ссылка найдена | кнопка «Открыть» |
| `not_found` | сервис ответил, песни нет | `—` |
| `unavailable` | не удалось проверить: нет ключа, таймаут или кончилась квота | ссылка «Искать», открывает поиск на этом сервисе (`searchUrl`) |

Ошибка одного сервиса не ломает ответ остальных. Коды ответа: `200`, `400` без данных для поиска, `429` при превышении лимита.

Требования:

- Таймаут на сервис 4 секунды, на весь ответ не больше 5 секунд. Сервисы опрашиваются параллельно.
- Кэш хранится на диске и переживает перезапуск, ключ — нормализованный запрос. Срок: `found` 30 дней, `not_found` и «нет совпадения на странице поиска» (`no_match`) 24 часа, остальные сбои не кэшируются.
- Ссылки в ответе проверяются по белому списку доменов сервисов.

## 8. Сайт

- Один экран, без сборки и фреймворков, тот же стиль, что у приложения: тёмная тема, Golos Text, жёлтый акцент.
- Форма поиска всегда сверху, под ней обложка, название, исполнитель и список сервисов.
- Пока идёт поиск, показывается подпись «Ищем на сервисах…».
- Кнопки: «Скопировать» у каждой ссылки и «Скопировать ссылку на страницу».
- Параметры всегда отражаются в адресе, поэтому любой результат можно отправить ссылкой.
- Работает на телефоне, ширина от 320 px.
- Сервер подставляет `og:title`, `og:description` и `og:image` прямо в HTML, чтобы в Telegram показывалась карточка: роботы Telegram не выполняют JS. Обложка подставляется, если результат уже есть в кэше.
- Страницы с параметрами закрыты от поисковиков через `noindex`.
- В подвале указано, что сервис неофициальный и не связан с перечисленными площадками. Ссылки на политику конфиденциальности в подвале пока нет.

## 9. Приложение и безопасность

### Кнопка в приложении

- В строке плейлиста при наведении рядом с «Скопировать» появляется кнопка «Уйти на сайт».
- Адрес строится через `URLSearchParams` из данных трека: `singer`, `songname`, `album`, `duration`, `ym`.
- Открывается в браузере через `shell.openExternal`. Метод моста принимает только данные трека, адрес строит главный процесс.
- Адрес сервиса (`YJam.LINKS_URL`) выводится из `YJam.SERVER_URL`. Когда появится домен, он заменит эту строку; правка `shared.js` затрагивает расширение, поэтому версия манифеста +1.

### Безопасность и данные

- Ключи API только в переменных окружения на сервере. В репозитории — лишь `.env.example`. IP сервера в коммиты не попадает.
- Всё, что подставляется в HTML, включая `og:*`, экранируется: параметры ссылки может придумать кто угодно.
- Лимит запросов на IP: 30 в минуту (подобрать на этапе 0). Запросы из кэша лимит тратят, но внешние API не вызывают.
- Дневной предел запросов к YouTube задаётся настройкой. После него YouTube отвечает `unavailable`, остальное работает.
- В логах нет IP и текста запросов, только счётчики. `docs/PRIVACY.md` дополняется: при нажатии кнопки название трека уходит на наш сервер и внешним API.

### Устройство

```
links/
  server.js          HTTP, кэш, лимиты, HTML с og:*
  search.js          параллельный опрос сервисов
  match.js           нормализация и оценка кандидатов
  providers/         по файлу на сервис
  public/            страница: index.html, app.js, style.css
  test/              тесты и записанные ответы API
deploy/
  Dockerfile.links   отдельный контейнер рядом с сервером комнат
```

Сейчас сервис отвечает через Caddy сервера комнат на `/links/` (`deploy/deploy-links.sh`), портов наружу у контейнера нет. Когда появится домен, nginx на VPS сможет принимать его на 443 и передавать запросы сюда.

Node 22, ESM, встроенный `fetch`, минимум зависимостей, как в `server/`. Хранилище кэша: `node:sqlite` на томе Docker, проверить на этапе 0. Сервер комнат не меняется: падение одного сервиса не затрагивает другой.

## 10. Этапы и приёмка

| Этап | Что делаем | Готово, когда | Состояние |
| --- | --- | --- | --- |
| 0. Проверка | С VPS вызываем API всех сервисов, решаем вопросы из раздела 11 | есть таблица «работает / нет / сколько стоит» | сделано, кроме API с ключами |
| 1. Бэкенд | `/api/search`, сопоставление, кэш, лимиты, тесты | эталонный набор проходит | сделано, в наборе только Apple и Deezer |
| 2. Сайт | страница, параметры, карточка для Telegram | сценарии ниже проходят | сделано, карточка в самом Telegram не проверена |
| 3. Деплой | контейнер, Caddy, домен, CI | сервис открывается снаружи по HTTPS | сделано на тестовом адресе, домена нет |
| 4. Приложение | кнопка «Уйти на сайт» | кнопка открывает нужную страницу в браузере | сделано, настоящий клик не проверен |

### Критерии приёмки

- `?singer=kizaru&songname=trooper` сразу показывает найденные ссылки, у остальных сервисов прочерк.
- `?singer=...&album=...` показывает ссылки на альбом.
- Ввод в форму даёт тот же результат, что и ссылка с теми же данными.
- Отключённый сервис или кончившаяся квота не ломают ответ остальных.
- Повторный запрос приходит из кэша и не тратит квоту YouTube.
- Ссылка в Telegram показывает карточку с названием.
- Треки с ненормативной лексикой в названии находятся, версия без цензуры выбирается первой.
- **Эталонный набор:** 30 запросов на русском и английском, включая ремиксы, синглы, альбомы и треки с матом в названии. Не меньше 90 % верных ответов и не больше одной неверной ссылки. Набор хранится в `links/test/` и прогоняется без сети, на записанных ответах API.

### Что не входит

Скачивание и хранение музыки, плеер и превью на сайте, аккаунты, история, импорт плейлистов, кнопка в расширении, бот Telegram.
