## 1. Навести порядок в архитектуре

**Сделано, автор проверил в Chrome.** Общий код переехал, в расширении и приложении копий нет.

```
shared/             код джема и шрифты: один на расширение и приложение
extension/          только расширение: manifest, попап, виджет, фоновый скрипт
native/             приложение Electron
services/rooms/     сервер комнат
services/links/     сервис ссылок
deploy/  docs/  tools/  store/
dist/               сборки
```

**Как разрабатывать расширение:** `node tools/build-extension.js` (или с `--watch`) собирает его в `dist/extension/`, Chrome загружает эту папку. `manifest.json` и пути в коде остались прежними: сборка раскладывает файлы по тем же местам.

`deploy.sh` и `deploy-links.sh` проверены на настоящем сервере после переезда на поддомены (4 ноября).

**Осталось на будущее:** приложение берёт попап из `extension/popup/`, потому что по этому плану попап остаётся в расширении.

## 2. Одна папка со сборками

**Сделано.** Всё собранное лежит в `dist/`, вне git.

```
dist/
  extension/        локальная версия для тестов: папку загружает Chrome, очищается при каждой сборке
  builds/           готовые файлы: zip расширения для магазина и друзей, mac-apple-silicon.dmg, mac-intel.dmg, windows.exe
  native/           служебные файлы electron-builder, из них build-all копирует готовые файлы в builds/
```

## 3. Сборка и релиз при каждом мерже в `main`

**Сделано и работает.** Workflow `release.yml` собирает zip, два dmg и exe на машинах GitHub и обновляет релиз. Он срабатывает, если мерж менял расширение, приложение или сборку; мерж только с документацией или сервером релиз не трогает.

- **Номер релиза:** `v` + версия из манифеста. Новая версия создаёт новый релиз, при той же версии файлы заменяются. Сам тег при этом остаётся на первом коммите этой версии, настоящий коммит указан в заметках к релизу.
- **Одна версия:** приложение при сборке получает версию из манифеста (`native/electron-builder.config.js`).
- **Заменено:** старый релиз по тегу `v*`, workflow `desktop.yml` с тегом `desktop-v*` и задача VS Code «release tag».

**Если сборка упала:** релиз не обновится, публикация ждёт все сборки. Так сбой GitHub Actions оставил без релиза версию 1.2.21: для Mac не нашлось машины. Новый мерж не нужен, в Actions есть **Re-run failed jobs**.

## Проверить в yj-14

На настоящем экране и с аккаунтом, без входа треки не играют:

- Трек возвращается после Cmd+Q: с той же секунды, играет или на паузе, как было при выходе. Итог каждого запуска записан в `lastRestore` в `playback.json`.
- С кем-то в комнате плеер подстраивается под неё.
- Кнопка mute на сайте и наша понимают друг друга.
- Плеер ходит за курсором без рывков, в том числе между мониторами.
- Windows: плеер в панели задач и в Alt+Tab, при сворачивании в трей пропадает.
