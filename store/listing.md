# babushkin-jam — тексты для Chrome Web Store

Скопировать в Developer Dashboard (chrome.google.com/webstore/devconsole) по разделам.

## Пакет

- Архив: `dist/babushkin-jam.zip` — `sh tools/build.sh` или задача VS Code «Расширение: собрать zip». Только он: папка `extension/` — локальная версия с голубой иконкой.
- Видимость (Distribution → Visibility): **Unlisted** — по ссылке, или **Private** — только для указанных почт.

## Store listing

**Название** (берётся из манифеста): `babushkin-jam`

**Краткое описание** (из манифеста, до 132 символов):
> Неофициальное расширение: слушайте Яндекс Музыку вместе — общий трек, пауза и перемотка у всех в комнате.

**Категория:** Entertainment (Развлечения)

**Язык:** Русский

**Подробное описание:**

```
babushkin-jam — совместное прослушивание Яндекс Музыки. Создайте комнату, отправьте друзьям ссылку, и у всех будет играть один и тот же трек: синхронно, каждый в своём браузере.

Как это работает:
• Создайте комнату в панели «🎧 Джем» на music.yandex.ru и скопируйте ссылку-приглашение.
• Друзья открывают ссылку и нажимают «Войти в джем».
• Кто переключил трек — тот ведущий, у остальных включается тот же трек.
• Пауза и перемотка от любого участника применяются ко всем.

Важно:
• Это неофициальное расширение. Оно не связано с ООО «Яндекс» и не одобрено им.
• Каждому участнику нужен свой аккаунт и подписка Яндекс Музыки. Расширение не даёт доступа к музыке, которой у вас нет.
• Расширение работает только на сайте music.yandex.*.

Какие данные передаются: только пока вы в комнате — ваше имя (по умолчанию случайное животное), код комнаты, текущий трек и состояние воспроизведения. Сервер пересылает их остальным участникам комнаты и хранит только в памяти. Подробно: https://<JAM_DOMAIN>:8443/privacy
```

## Privacy practices

**Single purpose (единственное назначение):**
```
Синхронное совместное прослушивание Яндекс Музыки: расширение включает у участников комнаты тот же трек, паузу и позицию, что у ведущего.
```

**Обоснование разрешений:**

`storage`:
```
Хранит в браузере имя участника, код комнаты и адрес сервера джема, чтобы не вводить их заново.
```

Host permission `https://*.music.yandex.ru/*` (и .com, .by, .kz):
```
Расширение работает только на сайте Яндекс Музыки: читает, какой трек играет, и управляет плеером (пауза, перемотка, включение трека), чтобы синхронизировать участников комнаты. Попап находит открытую вкладку Яндекс Музыки, чтобы показать её состояние.
```

**Remote code (удалённый код):** No, I am not using remote code.
```
Весь JavaScript находится в пакете расширения. С сервера приходят только данные о состоянии комнаты (JSON) через WebSocket, код не загружается и не исполняется.
```

**Data usage — какие данные собираются** (отметить):
- ☑ **Website content** — название, исполнитель и идентификатор играющего трека, позиция и состояние воспроизведения.
- ☐ Personally identifiable information — не отмечать: имя участника — произвольный псевдоним, по умолчанию случайное название животного.
- ☑ **User activity** (Действия пользователей) — на сервер уходят пауза, плей, перемотка и смена трека. Отмечаем с запасом: недоуказанные данные — частая причина отказа.
- ☐ Все остальные категории (Health, Financial, Authentication, Personal communications, Location, Web history) — не отмечать.

**Подтверждения** (отметить все три):
- ☑ I do not sell or transfer user data to third parties, outside of the approved use cases.
- ☑ I do not use or transfer user data for purposes that are unrelated to my item's single purpose.
- ☑ I do not use or transfer user data to determine creditworthiness or for lending purposes.

**Privacy policy URL:**
```
https://<JAM_DOMAIN>:8443/privacy
```

`JAM_DOMAIN` — из `deploy/.env` (см. `deploy/.env.example`).

## Перед отправкой

1. Задеплоить сервер, чтобы страница `/privacy` открывалась: `sh deploy/deploy.sh`.
2. Проверить, что `https://<JAM_DOMAIN>:8443/privacy` открывается.
3. Собрать свежий `dist/babushkin-jam.zip`.
