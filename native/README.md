# babushkin-jam: приложение для macOS и Windows

Яндекс Музыка и совместное прослушивание в отдельном приложении, без браузера и расширения. Комнаты те же, что и в расширении: участники с приложением и с расширением слушают вместе.

## Что умеет

- **Яндекс Музыка внутри.** Войти в аккаунт нужно один раз, вход сохраняется.
- **Плеер:** трек и кнопки, комната открывается кнопкой «Джем». Поверх всех окон он лежит, пока включена кнопка с булавкой; она же есть переключателем в панели трея и галочкой в настройках.
- **Плейлист в плеере:** кнопка рядом со временем раскрывает вниз список треков, он прокручивается. Клик включает трек; в комнате это смена трека для всех, а нажавший становится ведущим. Сыгранные песни остаются в списке, даже если включить другой альбом, новые добавляются снизу. Список копится и при закрытом плейлисте, хранит до 1000 песен и живёт до закрытия приложения. При наведении на строку появляются две кнопки: скопировать ссылку на трек и «Уйти на сайт» (страница со ссылками на эту песню в других сервисах открывается в браузере, см. [ТЗ сервиса](../docs/SONG_LINKS_TZ.md)).
- **Три режима**, меню «Окно» или значок в трее:
  - полное окно;
  - только плеер;
  - свернуть в трей: окон нет, музыка играет.
- **Панель над Музыкой:** кнопка «Джем» с участниками комнаты, текущая версия, «Настройки», «В трей» и «Свернуть в плеер». Виджета на странице нет, его заменяет кнопка «Джем».
- **Обновление кнопкой:** когда вышла новая версия, на панели появляется «Обновить».
- **Джем и настройки — интерфейс расширения, отдельного окна для них нет.** Кнопка «Джем» открывает комнату: имя, сервер, ссылка, участники, код комнаты копируется кликом. Настройки приложения открываются кнопкой «Настройки» на панели, шестерёнкой плеера, пунктом «Настройки…» в меню и трее: режим окна, вид плеера, действие при закрытии, плеер поверх окон, горячие клавиши, а под гаечным ключом синхронизация и диагностика. Закрываются крестиком.
  - В полном окне джем открывается кнопкой «Джем» под ней, настройки — кнопкой «Настройки» справа на панели. Закрываются крестиком, повторным нажатием, кликом мимо или Esc.
  - В плеере разворачиваются вниз. Если снизу не хватает места, разворачиваются вверх, а сам плеер остаётся на месте.
- **Трей:** вместо системного меню своя панель (`src/tray/`): трек, кнопки плеера в одну строку, те же плеер и комната, что в попапе расширения, и тот же блок настроек (это одна страница, `?host=tray`), настройки и выход. На macOS открывается любым кликом по иконке, на Windows правой кнопкой, а левая показывает и прячет плеер. Иконку можно убрать галочкой в настройках.
- **Значок в Доке и повторный запуск** показывают окно текущего режима и режим не меняют. Если приложение свёрнуто в трей, открывается полное окно.

## Горячие клавиши

Работают из любого приложения. На Windows вместо ⌘ и ⌥ — Ctrl и Alt.

| Действие | Клавиши |
| --- | --- |
| Плей / пауза | ⌘⌥P |
| Предыдущий трек | ⌘⌥[ |
| Следующий трек | ⌘⌥] |
| Показать или скрыть плеер | ⌘⌥J |

Если сочетание занято другой программой, оно не сработает: занятые показаны в меню «Какие клавиши».

## Сборка и запуск

Нужен Node.js 22 или новее.

```bash
cd native
npm install
npm start               # запуск для разработки
npm run pack:mac-arm64  # ../dist/native/mac-arm64/babushkin-jam.app (Apple Silicon), без установщика
npm run dist:mac        # ../dist/native/babushkin-jam-<версия>-arm64.dmg и babushkin-jam-<версия>.dmg (Intel)
npm run dist:win        # ../dist/native/babushkin-jam Setup <версия>.exe
```

В VS Code (`Cmd+Shift+B`) задача «build» для Mac на Apple Silicon закрывает запущенную копию, собирает текущий код, заменяет `/Applications/babushkin-jam.app` и открывает приложение. Копию она закрывает заранее, потому что вторая копия не запускается, а сборка заменяет папку приложения. Вход и настройки при этом сохраняются: они лежат не в самом приложении.

Задача «build-all» (`sh tools/build-all.sh`) пересобирает всё сразу: приложение для обоих Mac и Windows и расширение. На экране шаги с галочками, полный вывод — в `dist/build-all.log`. Файлы с понятными именами появляются в `dist/builds/`, установленное приложение она не трогает.

Версия приложения берётся из `extension/manifest.json`, в `package.json` её поднимать не нужно. При запуске из исходников (`npm start`) видна версия 0.0.0, обновления не проверяются. Тесты обновления: `npm test`.

Обе сборки делаются и на Mac. На GitHub их собирает workflow «Release» при мерже в `main`, готовые файлы — на странице [релизов](https://github.com/imbabyboy/babushkin-jam/releases).

## Первый запуск собранного приложения

Приложение пока не подписано сертификатом разработчика, поэтому система его предупредит:

- **macOS:** если приложение скачано из интернета, разрешите запуск в «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть» или выполните `xattr -cr /Applications/babushkin-jam.app`. Устанавливайте приложение в «Программы», а не запускайте из окна dmg: оттуда кнопка обновления не сможет его заменить.
- **Windows:** в окне SmartScreen нажмите «Подробнее» → «Выполнить в любом случае».

На macOS при обновлении кнопкой разрешать запуск не нужно: файл, скачанный самим приложением, не попадает в карантин.

## Обновления

Через 10 секунд после запуска и раз в 6 часов приложение спрашивает у GitHub последний релиз. Если его номер новее, на панели появляется «Обновить». Само оно не обновляется, чтобы не прервать джем.

По клику файл для своей системы скачивается во временную папку и сверяется с контрольной суммой из релиза, затем:

- **Windows:** запускается установщик в тихом режиме, он закрывает приложение и открывает новую версию.
- **macOS:** штатный автообновлятор Electron требует подписи, поэтому своя схема. Новая версия копируется из dmg рядом со старой, короткий скрипт ждёт закрытия приложения, меняет папки и запускает новую. При ошибке старая версия возвращается на место.

Если обновить не вышло или нет прав на запись, открывается страница релизов. Кнопка появляется только при новом номере: релиз с той же версией установленные копии не заметят.

## Как устроено

Код джема не копируется: он лежит в `shared/`, попап — в `extension/`, а `scripts/bundle.js` собирает из них `generated/`.

| Файл | Что делает |
| --- | --- |
| `src/main.js` | окна, режимы, трей, меню, горячие клавиши, правила для ссылок |
| `src/tray/` | дополнение к странице настроек для панели в трее: трек, кнопки плеера, нижние кнопки |
| `src/updater.js` | проверка релиза, скачивание и установка обновления |
| `src/store.js` | настройки в `settings.json`, интерфейс как у `chrome.storage.local` |
| `src/preload/music.js` | заменяет `content_scripts`: `page.js` — в мир страницы, остальное — в изолированный мир |
| `src/preload/no-overlay.js` | подставляется вместо виджета расширения |
| `src/preload/chrome-shim.js` | те части `chrome.*`, которыми пользуется код расширения |
| `src/preload/app.js` | мост для своих страниц: плеер, панель, настройки |
| `src/mini/` | плеер |
| `src/toolbar/` | панель над Яндекс Музыкой |
| `src/settings/` | дополнение к попапу расширения: из него `bundle.js` собирает настройки |
| `scripts/make-icons.js` | рисует иконки в `assets/`, запускается вручную |

Правка в `shared/` или попапе попадает в приложение после следующего `npm start` или сборки. Чтобы пользователи получили исправление `page.js`, нужно выпустить новую версию приложения: автообновления пока нет.

## Отличия от расширения

- Звук включается без клика по странице, поэтому кнопки плеера и горячие клавиши работают сразу после запуска.
- Запускается только одна копия приложения: вторая была бы ещё одним участником комнаты.
- Сайт видит обычный Chromium: приписки Electron и названия приложения убраны из User-Agent.

## Ограничения

- Работа зависит от внутреннего устройства сайта Яндекс Музыки, как и в расширении.
- Это неофициальное использование сервиса.
- Ссылка-приглашение открывается в браузере. В приложении вставьте её или код в поле панели «Джем» в плеере.

## Виды плеера

Выбираются в настройках («Вид плеера») и в меню «Окно» и в панели трея, настройка `miniView`.

- **Нано:** шестерёнка, плей и следующий. Подсказкам места нет.
- **Микро** (по умолчанию): обложка, название, джем, управление, повтор, случайный порядок и плейлист. Времени и перемотки нет.
- **Нормальный,** самый крупный: джем и кнопки окна; большая обложка, название, исполнитель и плейлист; время, управление посередине, случайный порядок и повтор; полоса перемотки.

Случайный порядок и повтор — режимы самого плеера сайта (`toggleShuffle`, `setRepeatMode` в `shared/page.js`), у каждого участника комнаты свои. Повтор по кругу: выключен, вся очередь, один трек, на «Моей волне» только выключен и один трек. Доступность кнопок решает сам сайт (`availableActions` текущей очереди): если он запрещает, кнопка серая.

## Будущие фичи

Идеи, ещё не начатые.

- **Лупа в плеере:** поиск песен прямо в мини-режиме.
- **Кнопка «Поделиться» в плеере:** скопировать ссылку на нужный сервис, например на Spotify, прямо в плеере, без перехода на сайт сервиса ссылок. Данные уже отдаёт `/api/search`; для точной ссылки на Spotify нужен ключ, сейчас там только поиск.
